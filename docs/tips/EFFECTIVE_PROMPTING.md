# 効果的なプロンプトの書き方

OpenCode に指示を出すときの文章を **プロンプト** と呼びます。
プロンプトの書き方次第で、結果の質が大きく変わります。

---

## 原則：人間の研究アシスタントに頼むように

OpenCode は優秀ですが、**あなたの意図を読むことはできません**。
研究室の新人に指示を出すように、**明確で具体的なプロンプト**を書きましょう。

---

## 良いプロンプトの5つの要素

### 1. 役割を与える

最初に OpenCode の「立場」を指定すると、結果の質が安定します：

```
あなたは経験豊富な認知神経科学の研究者で、
Python を使ったデータ解析と可視化のエキスパートです。
```

```
あなたは論文投稿を何度も経験した研究者で、
LaTeX の書式設定に詳しいアシスタントです。
```

### 2. 目的を明確にする

「何をしたいか」を最初に述べます：

```
【悪い例】
このデータを解析してください。

【良い例】
fMRI の時系列データから、特定の ROI の平均 BOLD 信号を抽出し、
条件間で比較する統計解析をしたいです。
```

### 3. 入力情報を具体的に

ファイル名、カラム名、データ形式を正確に伝えます：

```
【悪い例】
データを見て解析してください。

【良い例】
experiment_data.csv を読み込んでください。
カラムは 'subject', 'condition', 'rt', 'accuracy' です。
condition は 'A', 'B', 'C' の3条件です。
```

### 4. 出力形式を指定する

どういう形で結果が欲しいかを伝えます：

```
【悪い例】
結果を表示してください。

【良い例】
以下の形式で結果を表示してください：
1. 条件ごとの記述統計量（平均、SD、N）の表
2. 箱ひげ図（PDF で保存）
3. 統計検定の結果（検定統計量、p値、効果量）
```

### 5. 制約条件を伝える

論文用か、内部検討用かで要求が変わります：

```
【論文用の図の場合】
カラーは白黒印刷でも識別可能なグレースケールにしてください。
フォントサイズは論文規定に合わせてください。
解像度は 600 dpi、PDF 形式で保存してください。
ラベルは英語表記です。
```

## プロンプトの型（テンプレート）

研究で使いやすいテンプレートを用意しました：

### テンプレート 1: データ解析

```
あなたは[専門分野]の研究者です。
[ファイル名]を読み込んで、以下の解析をしてください。

目的：[解析の目的]
必要な処理：
1. [処理1]
2. [処理2]
3. [処理3]

出力形式：[表、グラフ、統計量など]
制約条件：[論文用、カラー制限など]
```

### テンプレート 2: コード作成

```
[プログラミング言語]で、以下の機能を実装してください。

要件：
- [要件1]
- [要件2]
- [要件3]

入力：[入力データの形式]
出力：[出力データの形式]

注意点：[パフォーマンス、可読性など]
```

### テンプレート 3: コード解説

```
以下のコードを[想定読者]向けに解説してください。
各行が何をしているか、なぜその書き方をするのかを説明してください。

コード：
[ここにコードを貼り付け]
```

## 実践的なテクニック

### テクニック 1: 段階的に指示する

一度にすべてを完璧にこなそうとせず、段階を踏みます：

```
Step 1: 「data.csv を読み込んで、中身を確認してください」
Step 2: 「欠損値があるかチェックして、あったら処理してください」
Step 3: 「条件ごとの記述統計を計算してください」
Step 4: 「群間比較のプロットと統計検定をしてください」
```

### テクニック 2: 修正・改善を繰り返す

```
1回目: 「折れ線グラフを描いてください」
2回目: 「線の色を青から赤に変えてください」
3回目: 「凡例を右下に移動してください」
4回目: 「軸ラベルを日本語にしてください」
```

一度で完璧を目指さず、**対話的に仕上げていく**のがコツです。

### テクニック 3: コンテキストを維持する

同じ OpenCode セッション内では、以前の会話が記憶されています。
新しいタスクを始める場合は、以下のように宣言すると切り替えがスムーズです：

```
「新しいタスクに移ります。今までの話は忘れて、
以下の新しい解析をしてください。」
```

### テクニック 4: 複数案を出させる

```
「このデータの可視化方法を3つ提案してください。
それぞれのメリット・デメリットを説明した上で、
最も適切なものを選んで実際にコードを書いてください。」
```

## 分野別プロンプト例

### 心理学・認知科学の場合

```
「実験参加者20名の反応時間データ（rt_data.csv）を解析します。
条件（congruent / incongruent）ごとに：
1. 外れ値の除外（平均 ± 3SD）
2. 記述統計量の算出
3. 対応のある t 検定
4. バイオリンプロット + 個別データ点のプロット

論文用の図として保存してください。」
```

### 生体医工学・脳科学の場合

```
「EEG データ（eeg_raw.set）を読み込み、
以下の前処理パイプラインを実行してください：
1. バンドパスフィルタ（1-40 Hz）
2. ICA によるアーチファクト除去
3. エポック抽出（-200 ms 〜 800 ms）
4. ベースライン補正
5. 条件ごとの ERP 平均波形のプロット

MNE-Python を使ってコードを書いてください。」
```

### 物理学・工学の場合

```
「実験で得られた時系列データ（oscillation.csv）を解析します。
サンプリング周波数は 1000 Hz です。
1. 時間領域での波形プロット
2. FFT による周波数解析（パワースペクトル）
3. 特定の周波数帯域（10-20 Hz）のバンドパスフィルタ適用後、
   包絡線を算出してプロット
```

## 避けるべきプロンプト

| 避けるべき書き方 | 問題点 | 改善例 |
|---|---|---|
| 「適当にやって」 | 意図が不明確 | 「条件ごとの平均値の棒グラフを描いて」 |
| 「いろいろ解析して」 | 範囲が広すぎる | 「記述統計と t検定を実行して」 |
| 「さっきの続きで」 | コンテキストが不明 | 「さっきの解析結果に追加で相関分析もしてください」 |
| 「いい感じに」 | 基準が不明 | 「フォントサイズ12pt、グレースケールで」 |

---

## まとめ

| やること | やらないこと |
|---|---|
| ✅ 役割を与える | ❌ いきなり抽象的な指示 |
| ✅ 目的を明確に | ❌ 「適当に」「いい感じに」 |
| ✅ 具体的なファイル名 | ❌ 曖昧なデータ指定 |
| ✅ 出力形式の指定 | ❌ 結果の形を指定しない |
| ✅ 段階的に指示 | ❌ 一度に全部やらせようとする |
| ✅ 繰り返し改善 | ❌ 初回で完璧を求める |
